# 要件定義書 — DOKIPON Commerce 5D Design Atlas

## 1. 対象・事実の区分

- 対象コード：`SayAtelier/DOKIPON`、`main`、コミット `1756173c04ddb11306a357927d05b1cc4ceac872`。
- 確認できる資産：Flutter Web・モバイル・LINE 向けアプリのエントリポイント、Rust Commerce サービス群、OpenAPI 3.1 契約。
- `feliture.shop` は公開 EC 体験の参考情報であり、当該リポジトリとの本番システム同一性は未確認。
- ソースから確認できる構成要素は **Implemented**、設計した呼出関係は **Designed**、イベントシミュレーションは **Hypothetical**。本番観測は含めない。

## 2. 機能要件

| ID | 要件 | 設計対象 | 受入観点 |
|---|---|---|---|
| REQ-001 | 商品閲覧 | `n.catalog` | 商品一覧と個別商品の契約整合性 |
| REQ-002 | カート管理 | `n.cart` | 書込み時の冪等性・競合制御 |
| REQ-003 | 在庫整合性 | `n.inventory` | 在庫不足時に注文処理を進めないこと |
| REQ-004 | 注文・決済 | `n.payment` | `payment_unknown` と成功・失敗の厳密な区別 |
| REQ-005 | 認証・認可 | `n.identity` | 不正なアクセスの拒否 |
| REQ-006 | チャネル連携 | `n.web`, `n.app`, `n.line` | 各クライアントと BFF 間の契約互換性 |

## 3. アトラスに関する要件

1D は編集可能なプロンプト、2D は全要素を探索できる平面グラフと独立した工程図、3D は階層化された空間グラフ、4D はイベント駆動の動的 3D、5D は同一エンジンに対する条件付き介入・再計算とする。0D は存在性確認であり独立画面は持たない。

## 4. 非機能要件

- 2D・3D・4D・5D の ID を共通化する。
- シミュレーションは描画フレームレートに依存しない。
- 設計用イベントに実決済・本番 API を使用しない。
- HTML エントリに外部 CDN を要求しない。
- 未確認の本番データベース構成や実測結果を断定しない。

## 5. 既知の制約

ブラウザー依存の WebGL は使用環境で異なるため、利用不能時は「DEGRADED」と明示した Canvas 投影へ切り替える。右記は品質保証上の代替であり GPU 3D の合格証明ではない。
