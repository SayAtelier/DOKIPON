## 3. 0D〜5D 機能要求の電商への写像

Atlas 的 0D–5D 在本项目中不作为可视化存在，而作为工程约束：

| 维度 | Atlas 原义 | 本仓库落点 |
|---|---|---|
| 0D 事实门禁 | 证据等级 | 每份文档/代码注释的 `[证据等级]` 标记 |
| 1D 结构 | 类型化 Node/Edge | `contracts/openapi.yaml` + `commerce-core` 类型 |
| 2D 语义 | UML/ER/时序 | `03-detailed/` 的 OpenAPI + ER + FSM |
| 3D 空间 | 部署拓扑 | `02-basic/` 的三 zone 拓扑 |
| 4D 时间 | 状态机事件时间线 | `Order.trail`（每次转移落一条 TrailEntry） |
| 5D 因果 | 干预与反事实 | Saga 补偿 + `PaymentUnknown` 对账 |

| FR-CORE-06 | LIFF 利用時は外部ブラウザ/非ログイン状態に対応する → GuestSession | [Observed] |
| FR-CORE-07 | UI 操作結果を Graph Revision 相当（Order.trail）に紐づけられる | [Observed] |
| FR-CORE-08 | Web/Android/iOS/LIFF の API 差を Bridge で分離 | [Observed] |

## 6. 要件優先度

**Must**: 证据等级、金额权威性、状态机完整性、幂等、库存不负、所有权校验、幂等键强制、problem+json。
**Should**: LINE SDK 降级路径、通知幂等、可观测性阈值。
**Could**: 商品レビュー機能、検索、外部 PSP 接続、実決済。
