# GemArc Commerce

由 `docs/gemarc-5d-design-atlas/` 衍生的电商系统：**Rust/Axum 微服务后端** +
**三种 storefront 发布形态**（App / Web / LINE MINI App）+ **提议中的后台 API / Flutter console**。

```
D:/DOKIPON
├── docs/ecommerce/          改写后的设计文档（IPA 风格，带证据等级）
├── contracts/openapi.yaml   OpenAPI 3.1 契约（23 paths / 24 schemas）
├── services/                Rust workspace，8 个当前 production crates；后台 crate 为提议项
├── packages/                4 个共享 Dart/Flutter package
└── apps/                    shop_app (Android/iOS) · shop_web (Web) · line_web (LINE MINI App) · admin_console（提议）
```

cd apps/shop_app && flutter run \
  --dart-define=GEMARC_CHANNEL=app \
  --dart-define=GEMARC_API_BASE=http://10.0.2.2:8080   # Android emulator → host

### 3.3 LINE 接线的关键点

- `apps/line_web/web/liff_bridge.js` 是**唯一**触碰 LIFF SDK 的地方，只向 Dart 暴露
  `{ready, isInClient, isLoggedIn, idToken, errorCode}`。
- SDK 加载失败 → `SDK_LOAD_FAILED` → 降级为普通 Flutter Web，**不重定向、不刷新**。
- 外部浏览器 / 未登录 / 同意撤回 → 一律落到 **GuestSession**，可浏览不可购买，**无登录循环**。
- `--dart-define=GEMARC_LIFF_ID` 只编译公开的 LIFF ID。**Channel Secret 不得进入本仓库。**

## 4. 三条不可妥协的规则

1. **金额是整数最小单位。** 服务端 `Money` 与客户端 `Money` 都拒绝负数、拒绝跨币种相加、溢出报错。
   任何 `double` 承载业务金额都是缺陷，不是风格问题。
2. **`payment_unknown` 不是失败，也不是成功。** FSM 中该状态**没有**通向
   `PaymentAuthorized` 的边；客户端只轮询状态，永不重新提交。这是防重复收款的唯一保证。
3. **服务端是唯一权威。** 客户端提交的小计只影响显示；下单时按目录价格重算。
   库存、归属、金额的判定全部在服务端。

## 5. 当前不能做的事

`04-detailed/セキュリティ設計.md` §5 列出了 9 条 Release Blocker，其中关键几条：

- 各服务目前是**进程内存存储**，Postgres 未连接（DDL 已在文档中给出，未执行）。
- 支付是 `ProviderScript` 驱动的模拟，**没有连接任何真实 PSP**。
- TLS、secret manager、速率限制的分布式化未实施。
- **LINE MINI App 平台审核未通过**，`index.html` 中的隐私政策 / 提供方 meta 仍为空。
- RPO 24h / RTO 4h 是**设计目标，未演练**。
