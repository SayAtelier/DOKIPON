# テスト設計書（UT / IT / ST / UAT / Security / Cross-platform）

## 1. テストレベルと完了基準
| Level | 粒度 | 期待証跡 | 完了基準 |
|---|---|---|---|
| UT | Pure Dart models, guards, graph, workflow | flutter_test 記録、coverage | Domain logic branch 90%以上を目標。未測定は未達扱い |
| IT | View/Controller/Bridge、Flutter+JS | 結合テスト・API mock | 失敗ケースで UI / semantics 非破壊 |
| ST | Web/mobile/LINE sandbox | 機種/OS/ブラウザ別証跡 | Causal, Auth, Persistence, Graph 切替が整合 |
| UAT | Architect, QA, reviewer | 要求 ID 単位の受入表 | Must 要件を確認し承認 |
| Security | Auth, PII, injection, WebView | セキュリティ報告 | S0/S1 欠陥 0 |
| Resilience | latency, timeout, offline, conflict | 時系列/補償ログ | 正常・異常・復旧が再現可能 |

## 2. 共通確認事項
- すべての Case で投入変数→Rule Guard→Rule ID→Graph Node ID→Patch→Terminal を追跡。
- 同一投入変数で同一順序・状態差分となる。
- 未知演算子は拒否。存在しない Rule/Node は拒否。無限ループは budget-exceeded。
- 正常 baseline と Failure Case の差異が実際の値の変更に限定される。
- `compensate` は必ず受け入れ可能な結果に確定した場合のみ `recovered`。
- 外部で決済、注文、LINE 通知などを実行しない。
- モデルが説明する業務は Hypothetical であると UI に明示。

## 5. 外部 API・LINE 環境
本番 LINE API に負荷テストを行わない。SDK mock を用いて `init failure`, `isInClient false`, `loggedIn false`, `permission denied`, `external browser` を評価する。Publish channel 認証、手数料/決済、LINE 審査は別途受入。

## 6. テスト環境の報告義務
Flutter SDK/OS/ブラウザ/Device、commit SHA、seed、全テスト合格数、失敗再現手順、coverage report を記録。外部環境未実行の項目を PASS としない。
