# 要件定義書（Requirements Definition）

## 1. ステークホルダー
アーキテクト、開発者、QA、セキュリティ責任者、業務承認者、運用担当、AI Agent、モバイル/LINE チャネル担当。

## 2. 業務要求
BR-01 証拠と仮説の混同を避ける。BR-02 視点を切替えても Node/Edge の安定 ID を保持。BR-03 通常/異常/境界/複合/復旧ケースを計算機で再現。BR-04 同一ワークフローの機械可読表現を維持。BR-05 Flutter Web と将来のモバイル/LIFF で共通ドメインを維持。

## 3. 0D〜5D 機能要件
| 次元 | Input | Output | 合格条件 |
|---|---|---|---|
| 0D 事実 | Repository/公開証拠 | 事実、証拠 ID、検証等級 | 証拠なしノードは Observed に昇格しない |
| 1D 構造 | Canonical Graph | タイプ付き Node/Edge | 多重辺・自己辺・方向が保たれる |
| 2D 意味 | UML/ER/DFD/Workflow | 図記法とポート表現 | 標準図式が意味を損なわない |
| 3D 空間 | Building/Floor/Room Mapping | 切替可能な空間図 | 部屋は仮想表現として追跡可能 |
| 4D 時間 | 状態・イベント | 順序あるタイムライン | 再生/シークで同じ結果 |
| 5D 因果 | Guard・注入変数・ルール | 分岐・差分・補償・反事実 | ルールから毎回再計算・停止保証 |

## 5. 横断的要件
- FR-CORE-01: 各 Node/Edge は不変の安定 ID および Evidence IDs を持つ。
- FR-CORE-02: 各選択対象は Node と Edge で異なる Inspector を表示する。
- FR-CORE-03: 退避は Graph Connectivity による関連度で決め、モデル本体を変更しない。
- FR-CORE-04: Semantic と Presentation は別ストレージ/別契約にする。
- FR-CORE-05: Rule Engine に任意コード実行を許可せず、ステップ数を制限する。
- FR-CORE-06: 本番外部 I/O をシミュレーションから起動しない。
- FR-CORE-07: LIFF 利用時は外部ブラウザ/非ログイン状態に対応する。
- FR-CORE-08: UI の操作結果を Graph Revision と紐づけられるようにする。
- FR-CORE-09: UML/ER/BPMN の正式な記法とラウンドトリップについては拡張フェーズの合格ゲートで実証する。

## 6. 要件優先度
Must: 証拠等級、Graph 整合性、Workflow Port 検査、正常/異常・補償分岐、Web ビュー、モバイル共通コア。Should: 本格 3D GPU Renderer、ストレージ、認証、日英全 UI 辞書。Could: 外部 Workflows 自動インポート、Agent MCP API。
