045D 来自规则计算

IPA REQUIREMENTS DEFINITION / 要件定義

需求定义

以 Feliture Flutter 商业应用为设计目标，区分可以在现有公开网站观察到的功能与尚待确认的业务要求。

证据等级：Designed · 目标设计Hypothetical · 后端假设Observed · 公开页面
非功能质量指标（设计目标，非实测结果）
安全性

令牌不进入因果日志；服务端执行授权；交易幂等与敏感信息最小化。

可用性

断网、失败、重试、前后台切换有明确状态与恢复设计。

性能

目标阈值应按设备等级、屏幕负载和 WebView 单独量测，不伪造 P95。

可访问性

WCAG 设计对照、字体缩放、键盘导航、色彩不作为唯一状态来源。

维护性

UI / Domain / Data / Platform Adapter 隔离，可追踪稳定模型 ID。

互操作

工作流语义与坐标分离；导入校验、版本迁移与语义损失检查。

安全 / 可追溯关键决定
ADR-001

共同业务模型用 Dart 定义；宿主平台能力通过 Adapter 隔离。

ADR-002

LINE 通过 Flutter Web + LIFF 接入，非原生 Flutter 运行。

ADR-003

3D 建筑仅是虚拟信息空间；不暗示真实部署结构。

ADR-004

设计网站独立离线启动；设计文档、事实证据和 CASE 数据只读。

ADR-005

支付、个人信息和实际订单不在设计推演中触发外部操作。

2D · STANDARD ENGINEERING DIAGRAMS

图谱、UML 与数据关系

从设计拓扑到 UML、ER 和时序图。Node 与 Edge 可独立点击；聚焦时其他对象按关系相关度退避。

点击节点或连线 · 关系优先的动态退避 · 设计数据不会因视图切换而改变
3D · LHC WEBGL · CANONICAL NODE–EDGE WORLD

统一三维图论架构

真正的 WebGL 三维模型。图论 Node 和 Edge 共享唯一 ID 与世界坐标，和 4D / 5D 使用完全相同的场景；楼宇、楼层与房间仅用于有语义的工程组织。

NATIVE WEBGL · LHC +X RIGHT · +Y UP · +Z FORWARD
鼠标拖动 = Yaw/Pitch · 滚轮 = Zoom · 点击宝石节点或关系线 = 独立检查 · 与 4D/5D 同模型—
4D · EVENT / TIME / STATE

事件与时间动态设计

4D = 同一个 3D 世界 + 可计算的事件、时间、状态与运动。切换 Case 或播放时间线，3D 节点与 Edge 同步响应。

5D · DETERMINISTIC CAUSAL ANALYSIS

因果分歧实验室

5D = 可注入正常/异常/边界/组合条件的 4D 三维场景。所有 Guard、补偿、反事实对比均重新计算后在同一 WebGL 场景中呈现。
