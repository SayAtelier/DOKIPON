    SessionController.boot() 的四步（storefront_state/session_controller.dart L48-L80）

    1. 向 LIFF 询问当前环境（是否在 LINE 客户端内、是否已登录、能否取到 id_token）
    2. 若能取到 id_token → 换取短期服务端会话，token 用完即弃、从不落盘
    3. 若 LIFF 不可用 / 被拒 / 在外部浏览器 → 退化为游客会话
    4. 只有游客会话也失败时，才提示「无法连接商店」

    五种降级提示（LIFF-002 ~ 006）

    LIFF-002 未配置不提示（开发构建不打扰用户）

    游客能不能结算

    分渠道。Session.canCheckout 对 line_user 恒为真；对 guest 则看渠道： LINE 渠道的降级游客（未登录、SDK 不可用）不能结算， 结算按钮是死的并说明原因；Web / App 渠道的游客可以结算 —— 网页店是物贩店，不是商品目录。 代价是：Web 游客买完之后无法再被识别（订单挂在 session 上， 而 session 只活在这个页面的生命周期里）。
